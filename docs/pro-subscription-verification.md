# Подтверждённая подписка PRO

Пользователь добавляет обычную HTTPS-ссылку. При добавлении и обновлении Nodera
отправляет новый случайный `X-Subscription-Nonce` и проверяет `X-Subscription-Proof`
до разбора YAML. Подтверждённая подписка получает метку PRO на главной странице,
странице подключений и в библиотеке. В интерфейсе отображается только тег «PRO».

Домен `312node.net`, название профиля, поля YAML и заголовок
`X-Subscription-Source: pro` не дают подтверждения сами по себе. Неизвестный ключ,
отсутствующая, некорректная или устаревшая подпись оставляют обычную рабочую подписку
без подтверждённой метки. Результат предыдущей проверки не переносится в новый ответ.

## Согласование с сервером

Контракт совместим с `api/subscription_signing.py` проекта vpsController:

- Ed25519, версия 1, payload и подпись в base64url без padding через точку.
- Подписаны `ASCII("vps-control/pro-subscription/v1") + 0x00 + payload_bytes`.
- Проверяются `source=pro`, `alg=Ed25519`, `v=1`, доверенный `kid`, SHA-256 точных
  байтов тела и полного URL запроса, совпадение nonce, `iat` и `exp`.
- Срок подписи ровно 300 секунд; часы выдачи могут опережать клиентские на 30 секунд.
- Запросы перенаправления не выполняются: пользователь указывает конечную HTTPS-ссылку.

Открытые ключи входят в приложение как `nodera/resources/pro-trusted-keys.json`.
Формат: JSON-объект `{ "<sha256_hex_от_открытого_ключа>": "<32_байта_ключа_base64url>" }`.
Ключи из ответа сервера не добавляются в список доверия. Замена и отзыв доверенного
ключа требуют контролируемого обновления приложения. Приватные ключи не входят
в клиент, исходники, установщик или релизный архив.

Для этого локального изменения подготовлена пара ключей. Закрытый файл находится
отдельно от репозиториев в `%USERPROFILE%/.vps-control/keys/pro-subscription-signing.pem`;
Windows ACL ограничен текущим пользователем. В JSON клиента записана только его
публичная часть. Сохраните закрытый ключ в защищённом месте и передайте его только
на доверенный сервер PRO, в `/etc/vps-control/subscription-signing.pem`, с правами `0600`.
В `/etc/vps-control.env` сервера настройте:

```ini
PRO_SUBSCRIPTION_SIGNING_KEY=/etc/vps-control/subscription-signing.pem
```

После установки обновлённого серверного кода и перезапуска
`vps-control-mihomo-manager.service` подписи станут проверяться этим клиентом.
До настройки сервера метка не показывается, загрузка и подключение продолжают работать.

## Сохранение результата

Локальная запись успешной проверки хранится вместе с профилем под защитой Windows
DPAPI. Она привязана к URL, нормализованной конфигурации и идентификатору доверенного
ключа. Копирование записи на другой URL или конфигурацию не переносит подтверждение.
Отзыв ключа в сборке клиента снимает подтверждение и у сохранённых профилей.

При перезапуске без сети сохраняется результат проверки последней загруженной копии.
Пятиминутный срок ограничивает приём сетевого ответа, а не время использования уже
проверенной локальной копии. Локальные правила, выбранные серверы и настройки устройства
сохраняются отдельно и не мешают проверке происхождения исходной подписки.

Проверка подтверждает происхождение полученной конфигурации. Она не шифрует подписку
и не запрещает её владельцу копировать собственную ссылку.
